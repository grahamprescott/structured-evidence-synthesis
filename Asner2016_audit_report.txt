## 2. CONTROLLED VOCABULARY CONSISTENCY

All controlled vocabulary fields contain only permitted values per the schema (verified programmatically across all 14 controlled-vocab fields × 30 rows = 420 cells). No non-permitted values found.

The following are **inconsistent codings** — same/near-same concept coded differently across rows:

### Issue 2.1 — Same v1_raw concept coded with two different `v1_code` values
- **Field:** v1_code
- **Rows affected:** 6, 7, 23 vs. 24, 25
- **Issue type:** Inconsistent coding
- **Values found:**
  - Rows 6, 7, 23: `"Anti-mining legal decrees and enforcement"` (v1_raw = "2012 government decrees and enforcement actions" / "2012 government action" / "government legal decrees and police actions")
  - Rows 24, 25: `"Anti-mining interdictions and enforcement"` (v1_raw = "interdictions" / "police action")
- **Suggested resolution:** These refer to the same underlying intervention class. Either harmonise to a single code (e.g. "Anti-mining enforcement actions") or, if the distinction between *legal/legislative decrees* and *physical interdictions* is intended to be kept, document the distinction explicitly in the ontology and apply consistently. Rows 23 and 24 in particular discuss the same body of action and should either both be split or both be merged.

### Issue 2.2 — Same v1_raw entity coded with two different `v1_entity_type` values
- **Field:** v1_entity_type
- **Rows affected:** 8, 9 vs. 26
- **Issue type:** Inconsistent coding
- **Values found:**
  - Rows 8, 9: `"Gold market price"` coded as `Context`
  - Row 26: `"Gold market price"` (v1_raw "reported gold market prices") coded as `Exposure`
- **Suggested resolution:** Choose one PECO role for gold price across the paper. Given that gold price is treated as an upstream variable acting on mining rate in all three rows, `Exposure` is the more defensible category (per the schema definition: "naturally occurring or background condition the population is exposed to"). Recommend recoding Rows 8–9 to `Exposure`.

### Issue 2.3 — Inconsistent v1_domain for "miner political organization"
- **Field:** v1_domain
- **Rows affected:** 12 vs. 13
- **Issue type:** Inconsistent coding
- **Values found:**
  - Row 12: `"Miner political organization"` coded `v2_domain = Social`
  - Row 13: `"Miner political organization"` coded `v1_domain = Governance`
- **Suggested resolution:** Same concept appears as outcome in Row 12 and exposure in Row 13. Domain should be stable across these. Recommend harmonising — `Social` is more defensible as the organisation is a grassroots phenomenon rather than formal governance.

### Issue 2.4 — V2 forest-loss codes split by geographic scope rather than concept
- **Field:** v2_code
- **Rows affected:** 14, 15 vs. 17, 18 vs. 19
- **Issue type:** Inconsistent coding (potentially deliberate)
- **Values found:**
  - Rows 14, 15: `"Forest loss"` (regional)
  - Rows 17, 18: `"Forest loss in Tambopata National Reserve"`
  - Row 19: `"Forest loss in Tambopata buffer zone"`

However, the schema already has `geographic_scope_raw` and `geographic_scope_code` fields specifically for this purpose. The current approach inflates the code vocabulary with geographically-qualified variants that should be a single code (`"Forest loss"`) disambiguated by the scope fields. Recommend collapsing to one `v2_code` and using scope fields for spatial disambiguation. This will materially improve cross-paper aggregability.

## 3. RAW-TO-CODE ALIGNMENT

### Issue 3.1 — Row 6 | rel_direction & rel_valence
- **Raw text:** "gold mining has continued despite numerous 2012 government decrees and enforcement actions against it"
- **Coded values:** `rel_exists=No`, `rel_direction=V1→V2`, `rel_valence=Indeterminate`
- **Issue:** The raw text claims an *expected* relationship (decrees → reduced mining) failed to materialise. Coding this as `rel_exists=No` with `rel_valence=Indeterminate` is internally inconsistent — if the relationship does not exist, the valence is *moot*, but the schema currently forces a value. The combination is defensible but the audit should note that the schema does not handle "intended-but-failed intervention" claims cleanly. See ontology recommendations.
- **Suggested value:** Keep as is, but flag for the reviewer; consider adding a note in `rel_exists_note` like "Paper claims decrees did not produce intended effect on mining" (which the extractor did add — confirms intent).

### Issue 3.2 — Row 7 | rel_valence
- **Raw text:** "A temporary downward inflection... was followed by a near doubling of the deforestation rate"
- **Coded values:** `rel_valence=Non-linear`
- **Issue:** Defensible but borderline. `Non-linear` per the schema means "the relationship changes direction or is described as non-monotonic". A temporary downward inflection followed by doubling does meet that test. However, this row arguably encodes *two* relationships (decrees → temporary decrease; absence/relaxation of decrees → rebound increase). Per the prompt's decomposition rule, it should have been split.
- **Suggested value:** Either split into two rows (Time t1: decree → decrease; Time t2: rebound → increase), or keep with `Non-linear` and add note in `rel_exists_note`.

### Issue 3.3 — Row 8 | rel_uncertainty_code
- **Raw text:** "the 2008 global recession bolstered gold prices"
- **Coded values:** `rel_uncertainty_code=Asserted`, `rel_uncertainty_raw="Not reported"`
- **Issue:** The verb "bolstered" is direct/unhedged, so `Asserted` is correct. But `rel_uncertainty_raw="Not reported"` is misleading — the raw hedging language IS "bolstered" (i.e. assertion language). Suggest using "bolstered" or leaving the field empty/Not applicable rather than "Not reported", which implies the field couldn't be coded.
- **Suggested value:** `rel_uncertainty_raw="bolstered"` (the assertive verb itself) or "No hedging present".

### Issue 3.4 — Row 9 | rel_uncertainty_code
- **Raw text:** "multiple factors have propelled increasing levels of informal... gold mining. First, the 2008 global recession bolstered gold prices"
- **Coded values:** `rel_uncertainty_code=Probable`, `rel_uncertainty_raw="Not reported"`
- **Issue:** The text uses the assertive verb "propelled" with no hedging. `Probable` is a downgrade not warranted by the source text. The extractor's note ("Bolstered prices listed as one of multiple causal factors") suggests the downgrade reflects the *plurality of causes* rather than authorial hedging — but that's not what `rel_uncertainty_code` captures. The schema definition is "the certainty level expressed by the authors", not the distinctness of the causal channel. The correct code is `Asserted`.
- **Suggested value:** `rel_uncertainty_code=Asserted`.

### Issue 3.5 — Row 9 | rel_conditionality_code
- **Raw text:** "Not reported" (in `rel_conditionality_raw`)
- **Coded values:** `rel_conditionality_code=Temporal`
- **Issue:** If `rel_conditionality_raw` is "Not reported", then `rel_conditionality_code=Temporal` is unsupported. The most defensible code when no condition is stated is `Unconditional`. The "post-2008" temporal scope appears in the *temporal_scope* field, which is the correct location for this information.
- **Suggested value:** `rel_conditionality_code=Unconditional`.

### Issue 3.6 — Row 11 | rel_conditionality_code
- **Raw text:** "Not reported" (in `rel_conditionality_raw`)
- **Coded values:** `rel_conditionality_code=Spatial`
- **Issue:** Same problem as 3.5 — if no conditionality is reported in the raw, the code should be `Unconditional`. The spatial information ("Andean → lowland Amazon") is captured in `geographic_scope_raw`/`population_raw`.
- **Suggested value:** `rel_conditionality_code=Unconditional`.

### Issue 3.7 — Row 11 | source_locus
- **Raw text:** No citation in the paragraph as printed; the introduction states "there continues to be out-migration of people from Andean regions" without a citation.
- **Coded values:** `source_locus=Synthesised from multiple sources`, `source_citation_raw="Not reported"`
- **Issue:** "Synthesised from multiple sources" implies the claim draws on multiple prior studies. There is no evidence in the text of multiple synthesised sources — the claim is simply uncited. More defensible options: `Original to this study` (treating the uncited claim as authorial assertion), or a "Not reported" entry. The current code overstates the evidentiary basis.
- **Suggested value:** Either `Original to this study` (most parsimonious) or flag for reviewer adjudication. Strongly recommend the schema add a "Uncited assertion" or equivalent value.

### Issue 3.8 — Row 14 | source_locus / paper_section

- **Coded values:** `paper_section=Introduction`, `source_locus=Cited from prior work`
- **Issue:** Correct, but worth flagging that this is the same lead author's *prior work*. The schema does not distinguish self-citation from external citation. If self-citation matters for downstream interpretation (e.g. weighing independence of evidence), this should be a flag. No code change required.
- **Suggested value:** No change; flag for ontology consideration.

### Issue 3.10 — Row 23 | rel_valence & rel_exists

## 6. ONTOLOGY REVISION RECOMMENDATIONS

Based on patterns in the issues found:

1. **Add a "Not reported" or "Not applicable" value to `method_type`.** Multiple rows (3.16) code `Review` as a default for cited claims where the original method is unknown. This conflates synthesis with primary methodology. Permitted values for `method_type` should include an explicit "Not reported / Unknown" option.

2. **Resolve the schema typo: `v1_entity_type` permits `Populations`, `v2_entity_type` permits `Population`.** Standardise to `Population` (singular) in both places. (Issue 5.1.)

3. **Reconsider how `rel_valence` interacts with `rel_exists=No`.** When the paper claims a relationship does *not* hold, `rel_valence` is undefined but the current schema forces a value (typically `Indeterminate`). This creates noise: e.g. Row 23's `effect_magnitude=40` reads like a positive intervention effect when it actually quantifies the *failure* of the intervention. Recommend adding a permitted value `Not applicable` for `rel_valence` when `rel_exists=No`, or explicit handling rules for negated/failed relationships. (Issues 3.1, 3.10, 3.14.)

4. **Tighten the `Synthesised from multiple sources` value in `source_locus`.** It is being applied to uncited authorial assertions (Issue 3.7). Either (a) define it more strictly (e.g. "claim attributed to ≥2 distinct prior studies"), or (b) add a `Reported without citation / Authorial assertion` value to handle the gap.

5. **Define explicit handling for compound V2 raw values.** The decomposition rule in the prompt is clear, but the extraction shows several compound rows (Rows 22, 27) where the V2 spans multiple domains and PECO categories. The schema currently forces a single domain code per row, which loses information. Either enforce decomposition more strictly in the prompt, or allow multi-domain coding (e.g. domain values like `Environmental + Social`). (Issues 2.5, 3.9, 4.6.)

6. **Separate geographic scope from `v2_code`/`v1_code` controlled vocabulary.** The current extraction embeds geographic scope into the `v2_code` (e.g. "Forest loss in Tambopata National Reserve" vs. "Forest loss"). The schema's `geographic_scope_*` fields are designed exactly for this purpose. Recommend a coding rule: `v1_code`/`v2_code` should be geographically-neutral; spatial qualification belongs in the scope fields. This will improve cross-paper aggregability. (Issue 2.4.)

7. **Tighten `rel_uncertainty_code` definitions to distinguish epistemic confidence from causal multiplicity.** Issue 3.4 shows the extractor downgraded `Asserted` to `Probable` because the source listed "multiple factors" rather than because the authors hedged the specific claim. The schema definition should explicitly note that `rel_uncertainty_code` reflects authorial *hedging language*, not the structural complexity of the causal pathway.

8. **Clarify whether `rel_conditionality_code` requires support from `rel_conditionality_raw`.** The current extraction has multiple rows where `rel_conditionality_raw="Not reported"` but `rel_conditionality_code` takes a substantive value (Issues 3.5, 3.6). The default when no condition is reported should be `Unconditional`, with a clear handling rule.

9. **Consider adding a flag for self-citation in `source_citation_raw`.** Issue 3.8 noted that Row 14 cites the same lead author's earlier work. For evidence synthesis, distinguishing internal/self-citation from independent corroboration may be analytically important. A simple Boolean `is_self_citation` field would suffice.
