# SAES v0.2.0-alpha — cross-trial summary

**Date:** 2026-05-19
**Trials:** three end-to-end pipeline runs in the same day, each in its own folder, each with a different research question and a different evidence regime.

| Trial | Folder | Question | Corpus | Mode |
|---|---|---|---|---|
| 1. VBAC | [`examples/vbac/`](examples/vbac/) | Predictors of vaginal birth after caesarean | 13 PDFs (pre-supplied) | Fresh PDF extraction |
| 2. Cocoa | [`examples/cocoa-biodiversity/`](examples/cocoa-biodiversity/) | How does biodiversity affect cocoa yields? | 8 PDFs (OpenAlex search + screen + download) | Fresh PDF extraction |
| 3. Gold-mining | [`examples/gold-mining/`](examples/gold-mining/) | Direct and indirect impacts of gold mining on biodiversity | 8 PDFs from prior 2022 review | Migration of 2022 manual coding into v0.2 schema |

Each trial's [REPORT.md](#) carries its own findings and caveats. This document compares them.

## Side-by-side numbers

| Metric | VBAC | Cocoa | Gold-mining |
|---|---|---|---|
| Papers | 13 | 8 | 8 |
| Extracted rows | ~170 | 57 | 105 |
| Consolidated edges | 27 | 31 | 43 |
| Unique nodes | 28 | 21 | 33 |
| Disagreement-flagged edges | 5 | 3 | 4 |
| Of which **substantive** disagreements | 4 | 1 (partial) | 0 |
| Of which **vocabulary artefacts** | 1 | 2 | 4 |
| Intervention-level rows | 0 | 2 (both cited) | 0 |
| Controlled-comparison rows | 0 | 3 | 0 |
| Numeric effect sizes captured | ~80% of rows | ~40% of rows | 0 rows |
| Trend-only rows | 6 | 3 | 0 |

The numbers themselves carry several lessons. The **cocoa run produced the fewest rows but the most diverse evidence types** (Intervention, Controlled comparison, Association). The **gold-mining run is the densest graph** (43 edges, 33 nodes — close to the SVG layout threshold) but the shallowest in inference level (uniformly Association). VBAC is the most schema-conforming corpus (clinical papers are written to standardised structures) and yielded the most numeric effect sizes.

---

## What worked across all three trials

1. **The 33-column row schema generalised across domains.** Clinical prediction, agronomic observation, and socio-environmental causal mapping all fit the same schema with no field additions needed. Some fields are uneven in use (Non-linear valence never used in gold-mining; Counterfactual never used anywhere) but the schema didn't break.

2. **The vocabulary-seeding step pays for itself.** All three trials had a seeded controlled vocabulary at the start (clinical predictor list for VBAC; biodiversity/shade codes for cocoa; the migrated 2022 codes for gold-mining). The seed reduced novel-`[UNVERIFIED]` codes to a manageable handful per trial (≈20 in VBAC, ≈9 in cocoa, 0 in gold-mining-by-construction).

3. **The disagreement-surfacing step is highly diagnostic.** It cleanly distinguishes vocabulary fragmentation (e.g. cocoa's native-vs-exotic shade tree split; gold-mining's `road_creation` vs `road_construction`) from substantive disagreement (VBAC's `inter_delivery_interval` direction conflict). The right next step is different in each case.

4. **The DAG construction succeeded at all three corpus sizes.** 21-node cocoa, 28-node VBAC, and 33-node gold-mining graphs all rendered legibly with a multi-tier left-to-right layout. Above ~35 nodes the SVG layout would need a different strategy (force-directed, faceted, or filtered to top edges).

5. **Three different input modes are now demonstrated.**
   - **Fresh OpenAlex pipeline** (cocoa): research question → search → screen → download → extract. The fullest demonstration of the protocol.
   - **Pre-supplied PDF corpus** (VBAC): start at the extract step. Faster; relies on a prior curator.
   - **Prior-coding migration** (gold-mining): translate an existing manually coded workbook into the v0.2 schema. Useful for retrospective standardisation and for combining v0.2 outputs with legacy reviews.

---

## Challenges

1. **No corpus contained any Counterfactual evidence; only one trial contained Intervention evidence.** Cocoa's two Intervention-level rows are both cited from prior work, not original. VBAC and gold-mining are entirely Association. Pooled effect sizes in the consolidated_edges.json files are vote-counting summaries, not meta-analytic estimates. The v0.2 protocol does not yet specify what a meta-analytic step would look like.

2. **Effect-size capture is highly uneven across domains.** Clinical papers report odds ratios and confidence intervals predictably; cocoa papers mix F-statistics, regression slopes, percent changes, and kg/ha differences with no shared unit; the gold-mining migration captured no effect sizes at all because the 2022 coding scheme did not include the field. The schema permits string-or-number `effect_magnitude` cells, which is permissive but means downstream pooling requires per-edge unit normalisation.

3. **Vocabulary fragmentation is a recurring failure mode that is caught by the audit phase, but not consolidation phase.** All three trials had cases where two codes were used for the same construct (VBAC's `induction_of_labour_current` vs `induction_of_labour_prior`; cocoa's `shade_tree_density_native` vs `shade_tree_density_exotic`; gold-mining's `road_creation` vs `road_construction`). The consolidation algorithm groups by string-identical code, so these appear as separate edges with smaller-than-true n_rows. The audit recommends merges in each case, but the merges are not applied automatically.

4. **The "stop short at the proximate endpoint" trap is real.** Gold-mining's most striking finding from the audit was that the vocabulary's `wildlife` outcome code was used zero times across 105 rows. The corpus stops at deforestation, mercury bioaccumulation, and human health — proxies for biodiversity outcomes, not biodiversity outcomes themselves. Cocoa has a milder version of the same problem (`cocoa_yield_stability` is described in text but coded under the magnitude-only `cocoa_yield`). VBAC avoids this because the outcome is operationally defined (vaginal birth: yes/no).

5. **Auditing in the same session.** Every audit was generated by the same LLM session as the extraction. A second-pass audit by an independent reviewer (different model, different session) is recommended for all three before any of the consolidations is treated as authoritative.

6. **Layout at 30+ nodes is at the edge of comfortable.** The cocoa SVG (21 nodes) reads cleanly. The gold-mining SVG (33 nodes) needed grouping rectangles, label suppression on small edges, and a callout box to explain where biodiversity sits and is still busy. Beyond ~35 nodes a force-directed or faceted-by-pathway layout would be more readable than the current tier-based design.

## Three trials, three different headline insights

- **VBAC:** the corpus supports a clinically usable predictor set, but the synthesis is at risk from one anomalous study (Bhide 2016 prior-vaginal-birth row). The safety-side edges into uterine rupture and maternal morbidity originate from `tolac_failure`, not from `vbac_success`, an issue that earlier versions of the DAG drew confusingly. The fixed DAG distinguishes the two outcome states explicitly.

- **Cocoa:** the headline "biodiversity helps cocoa yield" question does not have a single direction. Yield magnitude falls with shade cover/density, but rises with the functional diversity of shade trees and with yield stability under climate stress. The strongest causal-inference evidence (Toledo-Hernández hand pollination) points to pollination service as the binding biodiversity-yield link. 

- **Gold-mining:** the corpus is internally consistent and shows three converging pathways (direct biophysical, toxic chain, socio-economic loop). The most-replicated edge in any of the three trials is the gold-mining `aquatic_mercury_pollution → mercury_bio_accumulation` at n=11. But the corpus does not directly code biodiversity as an endpoint. The migration mode preserved 2022-era limitations: no effect sizes, no per-row method-type attribution, no Intervention rows.

## Forthcoming updates for v0.2.1

1. **Add a vocabulary-merge step between consolidation and DAG construction.** Take the audit's recommended merges and apply them programmatically before building the DAG. 

2. **Require explicit biodiversity / ultimate-outcome codes when the research question names them.** A protocol-level check: if the research question contains "biodiversity," "species," "community," or analogous terms, check that the seeded vocabulary contains them or discuss the outputs.

3. **Add a `cited_method_type` field alongside `method_type`.** Review papers carry both their own method (Review) and the cited paper's method (often Experiment or Statistical modelling). 

4. **Specify the meta-analytic step.** Right now `effect_size_pooled_within_stratum` is a vote-counting summary. Either rename it (`effect_size_summary_within_stratum`) or add a separate optional meta-analytic step with explicit pooling rules.

5. **Adopt a fourth canonical input mode: migration from prior coding.** The gold-mining trial demonstrated this works. The protocol should describe the column-mapping discipline (`prior_work_translation.md` as a required artefact) and the migration-specific caveats (no effect sizes; default `Association` causal level; paper-level method-type).

6. **Independent audit pass as a release gate.** None of the three trials' consolidations should be treated as authoritative until a second LLM (or human) has run the audit in a fresh session. Build this into the example outputs as a labelled "preliminary" status.

7. **Layout strategy for ≥30-node graphs.** Either an alternative renderer (force-directed via networkx + graphviz) or an explicit pathway-faceting strategy (one panel per causal chain). The current tier-based layout is at its limit in the gold-mining DAG.

8. **Benchmarking needed.** Need to benchmark this against human-coding for same papers, ideally by multiple reviewers.

## 

SAES v0.2 catalogued scientific evidence in a structured, transparent way in three separate domains. Further development and benchmarking needed to fully develop its capacities.
